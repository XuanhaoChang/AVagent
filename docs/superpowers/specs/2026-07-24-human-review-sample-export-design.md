# 人工复核样本导出设计

## 目标

新增一个独立脚本，将100条评测数据导出为“一条样本一个文件夹”的人工复核包。每个文件夹包含本地视频、参考图片、样本输入、标准答案和五组有效预测，方便在 VS Code 中用两栏同时打开 JSON 对比。

## 输出结构

默认输出到 `output/human_review_samples/`：

```text
sample_001/
├── video.mp4
├── reference_01.jpg
├── reference_02.jpg
├── input.json
├── gt.json
├── gpt_a.json
├── gpt_b.json
├── seed_a.json
├── seed_b.json
└── seed_c.json
```

文件夹固定使用源 CSV 行号 `sample_001` 至 `sample_100`，原始“序号”保存在 `input.json`，确保排序稳定且不受特殊字符影响。

## 内容规则

- `input.json`：序号、用户 Prompt、用户反馈和原媒体路径；不包含标准答案列。
- `gt.json`：只保存“思考过程及标准答案”中的最终 JSON 数组，不保存 `<thinking>`。
- 五个预测文件：分别读取 GPT-A、GPT-B、Seed-A、Seed-B、Seed-C 的 `pred.csv`，将“GPT预测结果”解析后以 UTF-8、`indent=2` 写入；数组元素、对象字段和嵌套字段必须实际换行，文件末尾保留换行，禁止输出单行 JSON。
- 视频和参考图片使用 `shutil.copy2` 实际复制，不创建软链接或硬链接。
- 保留媒体原扩展名，参考图片按 CSV 中的顺序编号。
- 不导出已知无效的 GPT-C。
- 不修改输入 CSV、预测 CSV 或原媒体。

## 校验与失败处理

- 以“序号”关联 GT 和五组预测，同时检查各 CSV 行数与序号集合完全一致。
- 每条 GT 和预测必须是 JSON 对象数组；任何缺失或解析失败都立即终止并指出样本、来源和原因，不静默跳过。
- 每个视频和参考图片必须存在且可读取。
- 默认拒绝写入已存在且非空的输出目录，避免覆盖人工复核内容。
- 使用临时目录完整生成并验证100条后，再将目录改名为最终输出目录，避免留下半成品。

## 验收

- 恰好生成100个 `sample_NNN` 文件夹。
- 每个文件夹有一个视频、全部参考图片、`input.json`、`gt.json` 和五个预测 JSON。
- 所有 JSON 均可重新解析，中文未转义成 Unicode 编码。
- 随机抽查至少三条，确认复制媒体与源文件大小一致、GT和预测来自正确序号。
