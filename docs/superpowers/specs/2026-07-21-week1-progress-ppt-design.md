# 音视频生成评测 Agent：第一周进展汇报 PPT 设计

## 1. 汇报定位

- 场景：项目第一周结束时的阶段汇报。
- 受众：项目导师与组内成员。
- 时长：约 10 分钟。
- 语言：中文。
- 核心目标：证明第一周已完成系统性的领域学习，并将调研结果转化为可执行的项目判断与第二周行动。
- 主要依据：`avgen_eval_survey.docx`；辅以 `音视频生成评测Agent_8周考核安排.docx`、`TMD-Bench.pdf` 和飞书页面“Agentic Eval”的项目定位与输入输出描述。

## 2. 叙事主线

采用“研究进展型”结构：

1. 本周围绕总体任务拆解了哪些研究问题；
2. 如何建立领域知识地图；
3. 文献调研得出的三条技术主线与四类方法；
4. 与本项目最相关的代表工作和关键启发；
5. 由调研收敛出的系统目标、评测维度与技术路线；
6. 本周完成情况、当前边界与第二周计划。

汇报不宣称尚未完成的模型复现或实验结果。对于八周安排中原计划在 W1 跑通的模型，只将其表述为“下一步验证对象”或“待完成项”，除非仓库中存在可验证的运行产物。

## 3. 逐页结构

### 第 1 页：封面

- 标题：音视频生成评测 Agent｜第一周进展汇报
- 副标题：从固定指标到“可提示、可定位、维度化”的智能评测
- 日期：2026.07.21
- 视觉：深色背景；抽象视频帧序列、时间轴与 bbox 共同构成主视觉。

### 第 2 页：本周目标与完成情况

- 以三项任务卡呈现：领域学习、方法梳理、项目收敛。
- 明确产物：完成一份系统调研报告，覆盖 Agentic Evaluation、缺陷接地、内在保真与音视频联合评测。
- 用“已完成 / 已形成判断 / 待实验验证”区分进度，避免将调研结论包装成实验结果。

### 第 3 页：本周调研范围与问题拆解

- 围绕总体任务拆为四个本周研究问题：评测 Agent 如何组织；视频缺陷如何分类；缺陷如何在时间与空间上定位；音视频联合评测增加哪些维度。
- 明确调研边界：本周聚焦方法、Benchmark、输出协议与可落地技术路线，不展开模型训练或完整实验。
- 视觉：四个研究问题围绕中心任务排布，直接承接后续知识地图。

### 第 4 页：本周建立的领域知识地图

- 严格保留调研报告表 1 的五类工作：Agent/可提示框架、MLLM-as-Judge/奖励模型、缺陷检测与时空定位、内在保真度/物理/人体、文本到音视频联合评测。
- 每类展示三项代表工作与该类的核心产出，避免用“三条研究主线”替代“五类工作分类”。
- 视觉：五条紧凑分类泳道，明确这是按评测产出形态组织的知识地图。

### 第 5 页：五类工作的产出形态与项目价值

- 对五类工作分别列出代表性工作、主要产出、是否具备时空接地、是否覆盖音视联合，以及对本项目的价值。
- 补回 VideoScore2、VideoReward、VF-Eval、VideoPhy-2、GRADEO、PhyAVBench、MTAVG-Bench 等原报告代表工作。
- 关键结论：五类工作需要被组合进同一系统；Agent 组织流程，Judge 提供判断，Grounding 与专用工具补足定位、人体和音视维度。

### 第 6 页：最关键启发——缺陷需要被接地

- 结构化输出协议：`{类别, 解释, 时间区间, bbox}`。
- 以一个示意视频帧展示 bbox、时间戳和缺陷标签。
- 突出 Skyra/ViF-Bench、BrokenVideos 对项目设计的直接启发。

### 第 7 页：由调研收敛出的评测问题体系

- 四个一级维度：文本/参考约束对齐、人体与手部保真、时序一致性、音视一致与同步。
- 每个一级维度展示 2–3 个代表子问题，如对象/动作错误、手指畸变/穿模、身份漂移/闪烁、事件同步/唇音同步。
- 视觉：层级分类树或四象限，不使用密集表格。

### 第 8 页：拟搭建的 Agent Loop

- 数据流：用户提示 + 参考图 + 生成音视频 → 帧采样与时间戳 → 评测 Skill/MLLM → 专用工具校验 → 结构化缺陷 → Benchmark 与误差分析 → 提示迭代。
- 将飞书页面中“可审计的结构化问题标注”作为输出原则。
- 明确方法定位：训练自由，以提示工程、工具增强和误差分析为主。

### 第 9 页：本周产出、尚未完成与风险判断

- 已完成：系统调研报告、代表工作对照、四维评测框架、候选技术路线。
- 尚未完成：模型/Benchmark 复现结果、真实 bbox 标注样例、基线实验。
- 风险：小区域缺陷易受视觉 token 压缩影响；跨帧缺陷依赖采样；通用 MLLM 专业性不足；音视同步需要专用度量。
- 视觉：完成项与风险项分栏，强调诚实边界。

### 第 10 页：第二周计划与可验收产出

- 定义 L1/L2/L3 缺陷分类与标注规范。
- 跑通一个接地评测基线和一个人体异常/音视同步工具中的优先项。
- 构建小规模样例集，形成真假/优劣成对样本。
- 输出 3 项可验收物：标注协议 v0.1、样例数据、基线运行记录。
- 结尾判断：第一周完成“认知收敛”，第二周进入“协议 + 基线验证”。

## 4. 视觉系统

- 比例：16:9。
- 风格：研究汇报型科技视觉，克制、清晰、可审计。
- 主色：深墨蓝 `101827`；内容页底色 `F5F7FA`；强调色使用青绿 `25C2A0` 与缺陷橙红 `FF6B4A`。
- 字体：标题使用微软雅黑/等线粗体，正文使用微软雅黑/等线；英文与数字可使用 Aptos。
- 贯穿元素：视频帧圆角卡片、时间戳胶囊、细线 bbox、层级标签。
- 每页至少一个信息图形；不使用纯标题加长项目符号页；不在标题下添加装饰横线。
- 论文与数据来源放在页脚小字，正文只保留对当前项目有用的结论。

## 5. 内容边界与准确性

- `avgen_eval_survey.docx` 是本周核心产物，PPT 的研究判断主要从该文档提炼。
- 8 周安排用于呈现项目目标和后续节奏，不用于反向声称本周已完成未留痕的工作。
- 飞书页面用于补充项目的实际定位：多图参考文生音视频、用户反馈优先、可审计结构化标注；不把其中“已实现模块”误报为当前仓库已完成成果。
- 文档中的“近一年”“最新”等表述在 PPT 中改为具体年份或工作名称，减少时效歧义。

## 6. 验收标准

- 9–10 页、10 分钟内可讲完。
- 本周进展、调研结论、项目技术路线和第二周计划四部分均有明确页面。
- 不出现无证据的实验数值或“已跑通”表述。
- 关键文字在投影环境下可读，正文不小于 15 pt，标题不小于 30 pt。
- 生成后进行文本提取检查、整套渲染、逐页视觉检查，并至少完成一次修复与复验。
